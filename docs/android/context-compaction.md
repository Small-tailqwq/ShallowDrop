# 长上下文后台压缩

Android 默认开启上下文压缩，在对话占用约 65% 的上下文窗口时后台生成摘要。发送下一轮时，有就绪结果则校验并采用；达到约 80% 时等待正在生成的摘要。Flash 和 V4 Pro 的窗口均按 1,048,576 token 计算，依据 [DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)。

「设置 → 通用设置 → 上下文压缩」包含开关与两个百分比，默认开启、65 / 80。关闭时阈值控件置灰，已设数值保留；确认时开关与阈值一起保存，取消不生效。共用刻度为 0–100%，蓝色表示 0 到开始阈值，绿色表示开始到等待阈值；80% 之后为斜线禁选区。蓝色水滴指针位于较低一层，绿色等待指针位于较高一层，分别具有 48dp 触摸区域和无障碍调节语义。

关闭压缩会取消正在生成的后台摘要，后续请求使用完整历史、忽略已有摘要；正等待摘要的发送继续使用原文。已有摘要检查点保留，重新开启后仍须通过内容和模型校验才会使用。服务端返回上下文超限错误时显示「当前对话已达到上下文上限，请新建对话」，提供「开启新对话」按钮，不在错误卡片提供重试。不会自动删除历史或另建会话；原会话可继续查看。上限由服务端判定，不把客户端字节估算当作硬性发送限制。

开始阈值至少为 1%，等待阈值最多为 80%，两者至少间隔 5 个百分点。拖动在边界停止，不推动另一指针；手填数字在完成、失焦或确认时限制到当前合法范围，空输入恢复上个有效值。设置模型同时校验上限和间隔，读取已有设置时限制到合法范围。点击确定后成对保存到 DataStore，后续请求直接读取新值，无需重启。拖动直接跟手，点击轨道与数字输入使用 180ms 缓动；变化的整数刻度触发轻触感，普通刻度间隔至少 40ms，端点使用区分反馈。动画与触感遵循系统设置。

优先使用最近一轮服务端返回的 usage（含缓存与输出）；usage 必须属于当前摘要版本。没有适用的测量值时，按请求文本的 UTF-8 字节数约除以四估算，文件块按估算值计入。文件解析、工具结果和未来输出的实际 token 数仍由服务端决定。

压缩请求使用同一模型和 API Key，关闭思考、工具及标题生成，输出上限 8192 token。摘要单独请求 API，会产生额外用量。近期最多两轮完整问答在估算不超过 64,000 token 时保留；待压缩前缀过小时总结当前已完成窗口。当前提问与续写前缀始终保留。

摘要使用前校验当前模型与被总结消息前缀的 SHA-256。分支选择和附件远端 ID 更新不改变内容指纹；编辑内容、切换到不同前缀或继续修改已总结的回答会使对应摘要失效。压缩期间新增的消息保留在摘要之后。

原始消息树继续用于展示、导出、重新生成和分支切换。已采用的摘要保存在锚点回复的 `contextSummary` 字段；回复的 `contextSummaryId` 标记本轮 usage 使用的摘要版本。Room 的消息 JSON 自动保存这些可选字段，无需更改数据库表。进程退出后恢复已采用的检查点，未采用的后台候选需要重新生成。

后台请求失败、拒绝、截断或摘要没有缩短上下文时，继续保留原始上下文；达到等待阈值时显示失败，下次发送可重试。停止当前回答不取消会话的后台摘要；删除会话、清空历史或整体导入时取消对应任务。

## 对照排查

- 本仓库 chat-demo 的 `src/services/chat/reply.ts` / `store.ts` 回传当前分支所有有效轮次，没有客户端自动摘要流程。
- DeepSeek Android 2.8.0（2026-11-13 样本）的客户端资源包含 `context_length_exceeded` 及达到上限后开启新对话的提示，未发现客户端自动摘要流程。此项为客户端静态排查，服务端内部策略未验证。

验证覆盖后台不阻塞、候选去重、前缀变化与模型切换、保留新增消息、失败重试、任务取消、检查点重新加载及请求输出上限。

## 模拟器可靠性与召回测试

`CompactionReliabilityTest` 为显式运行的设备测试，只有 instrumentation 参数 `liveCompaction=true` 时才请求模型，使用模拟器中已有的 API Key。测试将阈值设为 45 / 65，创建独立测试会话，保留用户已有会话。单轮结果写入应用私有目录 `files/compaction-test/`，连续五轮结果写入 `files/compaction-multi-test/会话ID/`，不记录 API Key。可通过 `-e class '完整类名#方法名'` 分别运行 `fixedCorpusRecallAndCheckpoint` 或 `repeatedCorpusRecall`。

固定样本由 30 轮原创旅行背景与 30 条随机封印代码组成，分散在前、中、后段，包含 3 条后续更正；另问 5 条未提供的信息。文本长度自然超过 65% 估算阈值，不伪造服务端 usage。基线通过原始上下文回答，基线问题和答案不写入待压缩会话。生产 ChatEngine 生成摘要并回答相同问题后，比较精确代码、更正采纳和 UNKNOWN 拒答；检查原始消息完整、检查点采用、重新创建引擎后恢复且不重复压缩，并记录 API 输入用量及耗时。

连续五轮测试在同一会话追加新材料，每轮比较压缩前后回答，评测问题和答案始终不写回会话。固定跟踪 27 条不再重复提供的旧事实，另外统计每轮新增事实、最新更正和未知问题；验证每轮采用新检查点、后续摘要包含前次摘要及原始消息保留完整。实测结果见[五轮测试报告](compaction-multipass-2026-11-16.md)。

固定样本是容易评分的事实保留测试。小说测试应另选前、中、后段的至少 30 个有明确原文出处的问题，覆盖人物关系、地点、时间顺序、数值与跨章节联系，另加 5 个原文没有答案的问题。标准答案与出处先固定，再分别对原始上下文、一次压缩和多次压缩评分。报告正确率、相对基线下降百分点、更正信息保留率、拒答率、实际 token 缩减率和等待耗时；每项保留样本数，不把原文未提供的信息算作召回失败。
